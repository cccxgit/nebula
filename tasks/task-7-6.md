# 任务

## 背景
我有一个路由器告警接入处理的业务，将路由器资源安装拓扑数据存储在分布式部署的nebula graph数据库中。当发生网络故障告警接入或者拓扑变更时，会对图数据库进行增删改查。现在识别到网络故障告警接入处理较慢，原因在图数据库语句执行慢（CPU和内存资源未完全利用）。因此计划开展性能调优解决。

## 任务诉求
1. 识别nebula graph和rocksdb的关键性能指标，然后在执行网络故障告警接入时，采集相关指标，用来指引性能调优
2. 根据nebula graph和rocksdb的源码，分析有哪些关键性能指标，这些指标含义是什么？如何指导性能调优？如何采集，采集形式是什么？建议对指标进行分级
3. 根据nebula graph源码，已知nebula graph内核指标接口为/stats，rocksdb指标接口为/rocksdb_stats和/rocksdb_property。因此本任务识别的指标需能够通过这些接口获取
4. 阅读nebula graph和rocksdb的源码，分析有哪些调优参数可以提升增删改查的性能？这些参数的含义是什么？这些参数如何使用？如何关联上面分析的指标，用来指导性能参数调优？
