# 盘点补充审查 日志快捷链接

初审 `INVENTORY-AUDIT.md` 中将 13 个服务日志快捷链接排除的建议需要调整。复查发现：它们全部使用同目录相对目标，目标全部存在、位于 `service-logs/` 范围内，并且真实日志已经列入 299 项初审候选；没有绝对路径或越界链接。

`analyze_runtime_rocks.py` 第 40 行按 `service-logs/{label}/nebula-storaged.INFO` 读取三个实例的日志。为了在目标 Linux 机器直接复算，应一并提交这些相对快捷链接。Git 保存的是 746 字节的链接目标文本，不会复制其指向的日志内容。

因此：初审候选快照仍为 299 项；发布选取应至少追加这 13 项，成为 312 项原材料，再加上本轮新增迁移文档、工具和校验记录。初审的普通文件字节数不会因追加符号链接而增加，最终发布包的路径数应以最终发布清单为准。

本补充没有修改初审 JSON、候选列表、历史证据或产品代码。链接逐项核查见 `inventory-followup.json`。Linux Git 克隆应保留链接；如果目标环境将 Git 链接检出为普通文本文件，应先修复检出方式，或者明确让新离线验证工具直接读取带时间戳的真实日志。
