# Prompt Patterns for Nebula Balance Bugfix

## 1. Read the codebase first

```text
请先不要修改代码。

我在排查 Nebula Graph 的一个复杂工程 bug：
storage 服务水平扩容后，执行数据均衡不稳定，经常失败。

请先做这几件事：
1. 解释与 data balance / storage balance 最相关的模块
2. 找出入口、核心执行链路、任务状态流转位置
3. 列出最值得先读的 10 个文件，并按重要性排序
4. 说明哪些地方最可能与扩容后执行失败有关

```


## 2. Build the hypothesis tree
```text
请先不要修改代码。

问题背景：
Nebula Graph 在 storage 服务水平扩容后，执行数据均衡不稳定，经常失败。
当前有可复现环境，也可以提供日志和代码定位信息。

请输出一棵根因假设树：
1. 最可能的 5 到 8 类根因
2. 每类根因对应的关键模块/文件
3. 每类根因应该看哪些日志或状态
4. 每类根因应该如何验证或排除
5. 优先验证顺序

请把不能从代码直接确认的内容标记为“假设”。
```

## 3. Map logs to code and state
```text
请先不要改代码。

下面是一次失败执行的数据均衡日志片段：
[粘贴日志]

请按以下格式分析：
1. 按时间线整理关键事件
2. 每个关键事件可能对应的代码模块/函数
3. 当前 balance 任务大概处在哪个状态
4. 失败前最后一个正常状态是什么
5. 最可疑的状态切换或异常处理点是什么
6. 我接下来应该重点查看哪些文件和日志关键词
```


## 4. Propose minimal fix plan
```text
请先不要直接改代码。

针对这个 bug：
Nebula Graph 在 storage 服务水平扩容后，执行数据均衡不稳定，经常失败。

请先给我一个最小修复方案：
1. 你认为最可能要改哪些文件
2. 每个文件大概要改什么
3. 哪部分是修复逻辑，哪部分是增强可观测性
4. 风险点是什么
5. 哪些改动必须配套测试

要求：
- 不要大规模重构
- 优先最小改动
- 明确标注假设
- 保持现有风格
```


## 5. Implement the patch
请根据刚才的分析，实施最小修复。
```text
要求：
- 不做无关重构
- 只改与该 bug 直接相关的文件
- 优先保证状态流转和异常处理正确
- 必要时补充诊断日志，但不要过度打印
- 除非明确不适合，否则补回归测试

交付格式：
1. 修改文件列表
2. 每个文件的改动摘要
3. 修复逻辑说明
4. 新增/修改测试说明
5. 风险点
```

## 6. Review the patch
```text
请审查这次修复，重点看：
- 是否真的修复了扩容后 balance 失败的根因
- 是否只是掩盖症状
- 是否引入新的竞态或幂等问题
- 是否破坏原有正常路径
- 测试覆盖是否足够
- 是否还缺少更好的可观测性

请按下面格式输出：
- 必须修
- 建议修
- 可选优化
```


## 7. Draft the PR

```text
请根据这次修复生成 PR 描述：
1. 背景
2. 现象
3. 可能根因
4. 修复思路
5. 具体改动
6. 测试与验证
7. 风险与影响面
8. 回滚方式
```
