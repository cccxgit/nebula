## 有效性检查

- 数据是公开真实记录；如裁剪文本，给出字符上限和裁剪比例；不重复扩充记录。
- 对比查询完整结果集合，记录查询集合、并发、LIMIT、预热、冷热缓存和失败率。
- 图写入确认与索引可见性分开计时；图数据与全文索引磁盘分开记录。
- 同机顺序运行两个方案；编译、下载、其他服务对测试造成的影响明确披露。
- 优化百分比只基于完成且可比的实测：吞吐提升 = 新/旧 − 1；延迟或资源减少 = 1 − 新/旧。
- 一亿条语料的来源规模、已下载行数、已导入行数、实际查询规模分别陈述。

## 必须披露的解释范围

- 数据许可：MS MARCO 语料仅限非商业研究使用，不能用仓库代码许可证推导语料可商用；本次比赛使用性质需符合数据方条款。
- 数据分层：来源 138,364,198 条；已校验下载字节、已规范化独立 VID、已导入独立 VID、查询实际覆盖规模分别填数。下载中的 sparse tar 的表观大小不代表有效下载量。
- 采样和投影：官方归档连续前缀，不是随机样本；128 字符为 Unicode 字符数、不是 UTF-8 字节数。填写裁剪比例，不能宣传为完整原文检索的存储成本。
- 查询语义：透明 CONTAINS 是大小写敏感的原文子串语义；TEXT_SEARCH / ES_QUERY 是分析器与 query-string 语义。两个实验分别报告。
- 分词器差异：当前名为 standard 的内置实现与 Elasticsearch StandardTokenizer 不保证中文、标点、撇号、连字符、Unicode 组合字符完全一致。需报告完整候选 ID 集合验证与失败案例。
- 原生功能矩阵：按 `fulltext-regression-cases.jsonl` 的 18 个 case 写实测通过/明确报错/结果不符。前缀、通配符、regex、fuzzy、range、boost、短语距离不能因解析器未报错就记为支持。boost case 的 VID 相等不能单独证明排名或加权正确。
- 索引完成：图写入确认、CREATE 自动回填、显式 REBUILD 的 job/task 完成、四个谓词完整 VID 可见性是不同时间点。报告是否重复重建，不能把全流程或局部流程混称纯索引构建时间。
- 候选集成本：本地 LIMIT 10 不保证存储侧或 graph 侧只物化 10 条候选。记完整命中数、峰值内存，拒绝用宽泛词在亿级未经门槛验证直接压测。
- 二进制来源：旧 Debug binary 的内嵌 Git 是 de9b3ed80，源目录当前 HEAD 是 b3457870fb7c11b29a35f364f2c23544ec41be01，二者不能混写为同一构建；同时保存 SHA256 与 `--version`。新旧构建配置、编译器/依赖和线程配置的差异必须列出。
- 资源与复制：新方案三个 storaged 的索引副本均计入；旧方案 3 graph replicas + ES 1 primary / 0 replicas 的冗余层级不同。PSS 按同一时间点求和，RSS 有共享页重复计数；进程 CPU 的 100% 表示一个逻辑核。
- 延迟口径：本客户端至 graph 往返，预热排除，成功请求 nearest-rank P50/P95/P99；同时列错误数、总请求与成功 QPS。200 次/查询的 P99 只由极少尾部样本决定，不能作稳定生产 SLA 承诺。
- 扩容估算：百万实测只是容量门槛输入。一亿外推通过也只允许下一有界阶段；失败或未跑项目保留“未测”，不制造一亿或 ES 提升数值。
