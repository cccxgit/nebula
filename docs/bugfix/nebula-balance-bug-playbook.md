# Nebula Graph 复杂 Bug 修复的 Vibe Coding 上手手册

适用场景：
- 你只能使用网页版 Codex
- 你通过 GitHub 仓库 + Codex 问答来推进工程问题
- 你正在处理一个复杂、可复现、可定位日志与代码的线上/准线上 bug
- 当前具体问题：**Nebula Graph 在 storage 服务水平扩容后，执行数据均衡不稳定，经常失败，需要修复**

---

## 0. 先明确：这不是“让 AI 直接修 bug”，而是“借 bug 学会工程化 Vibe Coding”

对初学者来说，最容易失败的方式是：
- 一上来就让 Codex “直接修好”
- 没有先建立问题边界
- 没有让 Codex 先解释仓库、模块、调用链、状态机、日志链路
- 没有固定提示词与验收格式

你应该采用下面这条主线：

**先 Ask 建图谱 → 再 Ask 做分析 → 再 Code 做最小修复 → 再 Ask 审查 → 再 Code 迭代 → 最后沉淀为 AGENTS.md / Skill / 维护文档**

---

## 1. 这个 Nebula Graph bug，为什么特别适合拿来练 Vibe Coding

这个问题具备很好的训练价值，因为它同时包含：
- **复杂分布式系统背景**：storage 水平扩容、数据均衡、任务执行状态、失败重试、节点拓扑变化
- **可复现环境**：适合让 Codex围绕“复现-定位-验证”闭环工作
- **日志与代码可定位**：适合训练“从日志回溯到状态机/模块/函数”的能力
- **修复不是纯算法题**：往往涉及并发、状态同步、时序、重试、异常处理、幂等、元数据一致性

这类 bug 特别适合用来练以下能力：
1. 读大仓库
2. 画调用链
3. 从日志定位代码路径
4. 从现象归纳根因假设
5. 做最小修复
6. 设计回归测试
7. 长期维护修复节奏

---

## 2. 你应该怎样用这个 bug 来上手 Vibe Coding

### 阶段 A：先建立“问题地图”，不要急着改代码

你的第一个目标不是修复，而是让 Codex 帮你建立一张“问题地图”。

你需要先搞清楚：
- 数据均衡功能的总体链路是什么
- storage 扩容后，哪几个模块参与了 balance
- 调度入口、任务状态、执行器、失败处理、重试逻辑分别在哪
- 元数据和 storage 实际状态在哪里汇合
- 日志从哪里打印、哪些关键日志最能对应代码状态

#### 提示词 1：读仓库与问题域

```text
请先不要修改代码。

我在排查一个复杂工程 bug：
Nebula Graph 在 storage 服务水平扩容后，执行数据均衡不稳定，经常失败。

请先做这几件事：
1. 用初学者能懂的话解释这个仓库里与 data balance / storage balance 最相关的模块
2. 找出相关入口、核心执行链路、任务状态流转位置
3. 列出最值得先读的 10 个文件，并按重要性排序
4. 告诉我阅读顺序
5. 说明哪些地方最可能与“扩容后执行失败”有关

请不要改代码，只做代码库理解。
