# 提示词模板

## 读仓库模板
```text
请先不要修改代码。

请把这个仓库里与 [问题域] 最相关的模块解释给我：
1. 入口在哪里
2. 状态如何流转
3. 关键文件有哪些
4. 哪些地方最容易出 bug
5. 建议我按什么顺序阅读
```

## 根因分析模板
```text
请先不要改代码。

问题现象：
[贴现象]

请输出：
1. 根因假设树
2. 每类根因涉及的文件
3. 每类根因对应的日志关键词
4. 验证方法
5. 优先级排序
```

## 日志定位模板
```text
请先不要改代码。

以下是一段失败日志：
[贴日志]

请分析：
1. 关键时间线
2. 对应状态流转
3. 对应代码位置
4. 最可疑分支
5. 建议追加哪些日志
```

## 最小修复模板
```text
请先不要直接大改。

目标：修复 [bug]
限制：
- 不大规模重构
- 只改相关文件
- 保持现有风格
- 优先补测试

请先给出最小修复方案，再实施。

输出：
- 问题理解
- 相关文件
- 修改方案
- 测试方案
- 风险点
```

## 审查模板
```text
请审查这次修复，重点关注：
- 逻辑正确性
- 并发/竞态风险
- 状态机完整性
- 幂等与重试逻辑
- 是否只是掩盖症状
- 测试覆盖

按“必须修 / 建议修 / 可选优化”输出。
4.6 PR 模板
请根据这次修复生成 PR 描述：
1. 背景
2. 根因
3. 修复思路
4. 具体改动
5. 测试与验证
6. 风险与影响面
7. 回滚方式
```
