# NebulaGraph 智能交互方案 Demo 脚本

## 1. Demo 目标

在 10 到 15 分钟内，让专家清楚看到：

- 这套方案已经跑通
- 不是简单查库
- 具备 AI 商业分析潜力

## 2. Demo 顺序

### 第一段：基础能力验证

演示问题 1：

- 查询 NebulaGraph 里有哪些 space

演示问题 2：

- 查看 `test_graph` 的 schema

演示问题 3：

- 查找 `person1` 到 `person5` 的路径

演示问题 4：

- 查询 `person1` 的邻居节点

讲解重点：

- 说明系统已经具备端到端真实查询能力

### 第二段：引入任务三数据方向

讲解内容：

- 如果把数据集换成 `Yelp Open Dataset`
- 图模型中将出现用户、商户、评论、品类、城市等实体
- 同样的工具链就可以支撑更高价值业务场景

### 第三段：展示高价值业务问题

演示问题 5：

- 帮我推荐某城市评分高、评论多、适合某场景的商户

演示问题 6：

- 找出某商户的最佳替代选择

演示问题 7：

- 哪些区域适合新开某类门店

演示问题 8：

- 近期差评最主要的原因是什么

演示问题 9：

- 哪些商户存在经营风险迹象

讲解重点：

- 这些问题比“查一条路径”更贴近企业决策

## 3. 讲解话术建议

### 技术话术

- Skill 负责把通用模型约束成图数据库专家
- MCP Server 负责把数据库能力标准化成工具
- NebulaGraph 负责执行真实图查询

### 业务话术

- 这个方案不是替代数据库，而是把图数据库变成可被自然语言调用的分析能力
- 因此它既有技术演示价值，也有业务决策价值

## 4. 结束语建议

- 当前已经验证技术可行性
- 下一步应围绕高价值业务场景建设试点数据与演示样例
- 从 PoC 到平台化的路径已经清晰
