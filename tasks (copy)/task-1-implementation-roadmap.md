# NebulaGraph 智能交互方案建设路线图

## 1. 建设目标

将当前已经完成验证的 `Skill + MCP + NebulaGraph` 原型，逐步演进为可在内部项目中稳定复用的智能图数据库能力平台。

## 2. 阶段划分

### 阶段一：PoC 与内部试用

目标：

- 建立可演示、可试用、可复现的基础能力

范围：

- 只读查询为主
- 路径和邻居分析
- schema 解释
- 图模型设计辅助

建议建设项：

- 固化 Skill 触发词与工作流
- 规范 MCP 配置
- 建立演示数据集
- 建立标准测试用例

预期产出：

- 内部 Demo
- 技术验证报告
- 试用反馈闭环

### 阶段二：工程治理增强

目标：

- 从“能用”提升到“可控、可管、可审计”

建议建设项：

- `execute_query` 读写分级
- 危险语句拦截
- 参数校验和注入防护
- 审计日志
- 结构化 JSON 返回
- 错误码与异常体系
- 服务监控指标

预期产出：

- 安全版 MCP Server
- 结构化结果协议
- 运维与审计规范

### 阶段三：业务语义增强

目标：

- 从“通用图工具”变成“懂业务的图智能助手”

建议建设项：

- 业务词典与语义同义词
- 领域提示词模板
- 常用业务图分析模板
- 结果解释模板
- 高价值业务场景最佳实践

预期产出：

- 行业/业务专属 Skill 扩展包
- 场景模板库
- 业务化问答能力

### 阶段四：平台化接入

目标：

- 接入内部平台形成共性能力

建议建设项：

- 前端图可视化
- API 网关接入
- 用户与角色权限体系
- 工单与审批链路
- 多租户支持
- 数据接入与同步流程

预期产出：

- 内部图智能平台
- 可复用服务接口
- 平台级能力目录

## 3. 关键优先级

如果资源有限，建议优先做以下三项：

1. 查询安全治理
2. 结构化结果输出
3. 高价值场景模板

这是因为当前系统最大的短板不是功能不够，而是：

- 缺治理
- 缺结构化
- 缺业务语义深度

## 4. 预期收益

推进后可带来的收益包括：

- 降低图数据库使用门槛
- 提升研发和分析效率
- 加速图谱试错和建模
- 提高图数据资产复用率
- 为内部智能问答和分析平台提供图能力底座

## 5. 风险控制建议

- 生产环境默认只读
- 危险 DDL/DML 必须审批
- 所有查询保留审计日志
- 引入 Prompt 与工具调用白名单
- 对图空间和租户做隔离

## 6. 里程碑建议

### M1

- 完成 PoC 演示闭环

### M2

- 完成安全与治理增强

### M3

- 完成业务语义模板建设

### M4

- 完成平台接入试点

## 7. 最终建议

当前建议不是“大规模全面铺开”，而是“先围绕高价值图场景做聚焦试点”，逐步沉淀共性能力，再平台化。
